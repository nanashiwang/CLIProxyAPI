## 行为说明

- 大请求切换不重新选账号，不重放已发送输入，不重复记录失败用量。下游 WS 与实际 HTTP/SSE 上游独立记录。切换后的增量请求明确要求完整重放。
- 中断仍需显式开启 `codex.response-steering: true`，默认关闭。账号 WS 开关、账号池权限、冷却和临时账号限制继续生效。丢弃部分输出后不得通过输出补全将其恢复。
- 跨账号清理仅作用于已证实换号的重试边界，保留同账号原生字段和客户端关联信息；未知来源不擅自全局清理。带连接上下文的请求不能跨账号继续执行。
- `GET /v0/management/auth-files` 的运行时账号增加 `execution_capacity`：`active`、`limit`、`unlimited`、`scope: "local"`、`observed_at`。普通本地模式 `limit=null, unlimited=true`；Home 模式共享上限未知，`limit=null, unlimited=false`。没有观测器时省略字段。
- `active` 来自实际生成执行路径，排队、计数接口、空闲 duplex 和租约归属不计入。取消不提前释放仍存活的生产者；原有错误结果与冷却判断完整保留。每个进程独立观测，不能相加解释为上游额度。
- React 卡片显示已知、未知、无限及明确有限上限达到时的状态。本次后端不引入新的并发调度限制。旧后端仍可打开管理页，新信息显示为未知。

### 发布验证发现的 Home 终止流竞态

首轮远端验证在 `TestHomeCodexTerminalStreamFailureUsesFreshDispatchOnNextRequest` 失败：Home 回收上游连接会取消执行上下文，抢先盖过已经产生但尚未穿过观测层的响应帧，误触发新的调度；后续复用只等待响应的测试连接导致五分钟超时。新增观测改变了调度时序，使已有取消边界问题暴露。

修复仅将下游传递绑定到客户端请求的取消边界：上游网络仍受 Home 执行上下文控制，连接、租约回收与客户端主动取消继续有效；初始帧和终止错误可以完整排出。未增加生产网络超时。回归测试验证原始 502 必须传递、首个请求只有一次派发，以及下一次请求使用新的 Home 派发和连接；另有先退休再转发的顺序测试（旧逻辑稳定失败），Home 终止流连续 100 次 race 回归通过。完整测试、相关 race、构建及管理 API 冒烟重新通过后再次提交发布。
