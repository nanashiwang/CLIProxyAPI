## Release delivery

Personal mainline verification runs the full suite, server build and smoke on Ubuntu with default CGO before creating a version tag and dispatches [release.yaml](../.github/workflows/release.yaml). All binary platforms must pass before publication. Final checksums use current Release downloads, validated against GitHub asset digests; rerun artifacts cannot substitute stale archive bytes. Darwin CGO archives use Intel macOS runners with explicit target-architecture checks. FreeBSD jobs reuse installed LLVM tools and install only missing prerequisites. Deployment patches use the previous published ancestor, excluding failed draft tags. [FreeBSD sysroot download](../.github/scripts/build-freebsd-cgo.sh) authenticates every source with a pinned SHA256 before extraction. [personal-container.yml](../.github/workflows/personal-container.yml) then builds and smoke-tests both native Linux architectures using the existing Dockerfile and publishes repository-owned GHCR tags. A manual run can select an existing published tag, verify its source commit, and retry only container delivery without retagging. The operator still owns production deployment.

Codex transport uses per-connection `x-codex-websocket-max-message-bytes` for pre-upload selection. An explicit peer close 1009 during upload and before any response text also permits same-account HTTP for independent requests. Active duplex and lease-bound attempts retain their transport. HTTP and WebSocket forward all `x-codex-exclude` values. Their final handshake values participate in connection reuse and exact continuation checks. Oversized stateful continuations require replay, and warmup never becomes HTTP generation. Structured `NO_MORE_RETRY` blocks same-account recovery; capacity rotation still obeys CPA admission, lease and delivery boundaries. See [November adaptation](CODEX_PROXY_NOV17_CN.md).

OpenAI-compatible providers persist optional `test-model` through management GET/PUT/PATCH and YAML reload. Empty selects the first configured model; this preference does not change gateway routing. The management test selector supports case-insensitive model search. Other provider families retain their existing test-preference semantics.

OpenAI-compatible providers and individual keys have persisted IDs. Rename, notes and reordering preserve account-pool membership; management mutations target provider ID with legacy fallback. Per-key notes appear in the editor, detail view and account groups. Legacy IDs are retained; only a unique matching historical pool binding is recovered. First load persists migrated IDs in the configuration. Ambiguous missing references remain inert.

The v8 integration retains personal account pools, exclusive leases, quota observations and usage/pricing under `/v8/management`, alongside the upstream grouped configuration, plugin and routing contracts. Legacy v7 YAML is normalized at the configuration boundary; personal root fields and OpenAI-compatible provider/key identities, notes and test-model survive canonical saves. V8 access-key rotation migrates pool permissions and leases before the new configuration becomes active. Legacy management endpoints remain available but new features use v8.

Streaming completion preserves the personal delivery boundary: a response terminal frame does not end a PoO-enabled stream before its proof or final error arrives. Internal model request cancellation retains upstream's empty-stream cancellation behavior. Native Codex model discovery applies personal account-pool authorization. Ordinary quota cooldown remains bounded at one hour; upstream forced cooldown is a separate layer. Authentication failures remain visible and ineligible for dispatch while the v8 refresh lifecycle can recover nonterminal failures.

Node installation and update understand both legacy and v8 block YAML. Targeted configuration updates retain unrelated provider and personal fields; unsupported inline parent maps fail before rewriting the file. Nginx management restrictions cover both v0 and v8 paths. The updater migrates only the installer-generated location with its management ACL marker; validation/reload failures restore the previous files. Release smoke uses the v8 contract with a legacy YAML input, grouped provider save/read/rename and the full personal usage insight flow. Go release builders follow the 1.26.10 module requirement, and deployment bundles pin the paired v1.28.3 CPA management release.

Quota reads recognize confirmed Codex access-token revocation. The v8 usage dashboard and records share the optional error_origin filter. Embedded GPT-6.2 pricing records the applicable Ultrafast period. Codex OAuth request preparation removes unused SDK IDs from inline replayed text.
