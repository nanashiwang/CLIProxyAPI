# 10 月使用统计与日志优化

本次选择性融合 `zyycn/codex-proxy-rs` 的四项改进，沿用 CPA 的 Go / React 实现。全仓跟踪起点、全仓审查基线与各功能适配来源保持独立。

## 使用体验与兼容

- **性能口径**：首次输出不再使用首个响应字节代替。详情分别展示首字节、首次输出、首次正文、首次推理及上游响应、引擎和 API 耗时。上游吞吐仅使用有效的单次响应时间；本地吞吐明确标注估算。旧记录仍保留 `ttft_ms`，缺少新指标时显示未知，不回填历史事实。
- **统计查询**：在读锁内复制选定时间段，锁外完成聚合；按数据版本缓存最多 8 份、每份不超过 2 MiB 的结果。缓存最长复用一秒，返回真实计算时间和区间。写入、迟到记录、保留期清理、导入、清空和重配置都会使旧版本失效。没有引入上游 PostgreSQL 表结构。
- **错误诊断与日志**：只保存枚举化失败原因，不保存错误文本、地址或凭据。运营文件日志使用异步批量写入、条数和字节双重预算，并为警告与错误预留容量。日志页显示本次服务启动后的丢失与写入失败累计数。流式日志与远程日志转发的丢失也计数；计量记录不采用该丢弃策略。
- **依赖安全**：管理前端通过 Bun override 将所有 `source-map-js` 实例固定为修复版 `1.2.2`，对应 GHSA-68fv-2mgg-jv7q。

## 保留的约束

账号池权限、空选择的含义、独占租约、连接续接、冷却、重试和预提交内存上限不变。Token accounting v2 的互斥分桶和历史计费快照不变。大于 256 KiB 的观测帧被跳过，转发数据不受影响；相应计时保持未知。正常关闭会排空已接收的运营日志，异常终止仍可能损失尚未写入的日志。

## 验证与发布

验证覆盖 Go 全量测试、相关包竞态检查、二进制构建、真实管理 API 冒烟、Bun 测试及生产构建。管理页面使用隔离的本地后端和模拟记录验收，包含桌面、390px 暗色、历史数据、错误原因与旧接口兼容。未调用真实上游模型，未部署线上服务。

在 Apple M5 的 5 万条模拟记录基准中，单次构建约 33.5 ms，缓存命中约 0.16 ms；该结果仅说明重复查询收益，不代表生产吞吐保证。未命中时仍需要扫描所选记录。

前端和后端分别使用现有主线发布流程。后端部署包固定对应前端版本，包含源码补丁、管理页面、部署说明和构建参数，并由流水线重新下载校验 SHA-256。
