# 2026-11-17 上游增量适配

本次融合三项行为，继续使用 CPA 的 Go / React 实现。全仓跟踪起点、全仓审查范围和各功能适配来源分别保存，未将上游当前 HEAD 当成整体适配基线。

| 改进 | CPA 的行为与边界 | 来源 |
| --- | --- | --- |
| 服务健康 | 独立展示服务成功率、服务失败、未完成、取消、调用方错误和未知。分母为成功、服务失败、未完成；无样本返回 null。总请求统计及费用不变。 | [3e33e84](https://github.com/zyycn/codex-proxy-rs/commit/3e33e84a45e740aaf15650c2ab26af5c3d3db88b) |
| WebSocket 限额 | 使用当前连接握手的 `x-codex-websocket-max-message-bytes`，按最终消息 UTF-8 字节数判断，仅超出才降级；替换固定 15 MiB 预测。 | [9f0d712](https://github.com/zyycn/codex-proxy-rs/commit/9f0d712671c66a3c6a2ea91f016c4f9c1eda4d95) |
| 停止同账号重试 | 读取错误对象或事件 headers 中的 `x-retry-metadata: NO_MORE_RETRY`；不从错误文案猜测。跳过同账号别名重试、刷新和等待。 | [914c007](https://github.com/zyycn/codex-proxy-rs/commit/914c00785c4000b83a3319edddc0fea387660ec9) |

统计基于保留的用量事件，不重建逻辑请求的最终结果，也不利用尚未结束的诊断快照猜测恢复成功。401、403、429 和网络故障属于服务失败；可识别的取消、调用方输入错误和未知记录单列。旧失败记录缺乏状态证据时保留未知，已有历史价格和 Token 数据不变。新版界面对旧后端保留原展示。

超限完整新请求在发送任何 WebSocket 正文前回退 HTTP；携带 previous_response_id、绑定既有连接的续接仍要求客户端完整重放。预热请求超限直接报错，不变成生成请求。缺失、无效或非正限额不作预测；重连重新读取限额，双向后续消息同样受当前连接限额约束。

容量、过载与限流的换号继续遵守既有账号池权限、租约、冷却和交付边界。其他明确停止重试错误直接返回；`Retry-After` 信息和原有流式交付语义保留。本次不加入智能调度或插件系统，也不部署线上服务。

每周监控对暂时性 GitHub API 失败增加最多三次尝试，等待 1、2 秒；401/403 等永久错误不重试。全部尝试失败仍产出失败报告。

验证：Go 全量测试、编译、管理 API 冒烟、定向 race；消息大小/续接/重试回归；前端测试、lint、类型检查和构建；本地使用统计路由桌面/移动端检查；19 项监控离线测试。
